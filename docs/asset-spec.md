# Common metric placement and source contracts

All placeable assets, including new daily props, use 1 unit = 1 metre, Y-up, XZ ground and default scale [1,1,1]. Imported drawing coordinates are archived separately and converted through an explicit physical estimate, never a camera/viewport fit.

`assets/catalog.json` enumerates reusable `asset.json` sources. Renderer-specific HTML is never an asset source. The current executable validation contract is `scripts/validate.mjs`; run it after every addition.

- Units: metres, right-handed coordinates; +X right, +Y up, +Z toward the front reference direction. Ground is Y=0. Rotation arrays are radians applied X, then Y, then Z. Camera transforms never change geometry.
- Root origin: center of the ground-contact surface. Base contact need not equal the clearance bounds center. Default scale is exactly [1,1,1].
- `dimensions`: X width, Y height, Z depth. `bounds.min/max`: exact axis-aligned rest-pose geometry extents. `footprint`: conservative XZ clearance rectangle in winding order; this is not a physics collider. Recompute rotated world bounds for placement checks. No collision solver ships in v1.
- `id` is stable, `version` a positive integer; `schemaVersion` is 1. Record estimated vs measured sizes in `measurement`. Include provenance and license; this lamp is original procedural geometry under CC0-1.0.
- Parts contain stable `id`, `parent` (null or part ID), metre `position`, radian `rotation`, local `pivot`, unit `rotationAxis`, `joint`, per-part `state`, geometry and material ID. Position is relative to the parent. Transform order: parent × translation × pivot × rotation × inverse pivot. v1 supports fixed joints only; axis metadata describes the reference axis, not an articulated joint implementation.
- Supported geometry: centered box (`size`) and Y-aligned cylinder/frustum (`radiusBottom`, `radiusTop`, `height`, `segments`, optional `openBottom` and `openTop`). Segments must be a multiple of four, from 8 to 128. All geometry is actual triangle data generated in metres, suitable for a shared 3D world.
- Materials have RGB [0,1] colors and optional `emissionWhenOn`. v1 switches bulb and shade appearance; it does not calculate cast light or shadows. Open-bottom shade is a two-sided single surface, not a thickness model.
- Asset `state` defines instance defaults; toggle actions name boolean state keys. Runtime instances deep-copy state. Never mutate shared asset data for interactions.
- Scene JSON contains schemaVersion and instances: id, assetId, assetVersion, position, rotation, scale and state. Unknown versions fail explicitly. Current preview storage is browser-local. Per-part animated state and migrations are future extensions.

## Adding a batch

First follow [production policy](production-policy.md): review cumulative and recent catalog coverage, existing previews and duplicates, then select a useful home/office/commercial interior theme. A batch has no mandatory ten-object size. Keep room/group counts distinct from new independent assets and prefer verified mixed-size scenes over small-object filler.

Create one directory per asset, author metric source and provenance, append catalog paths, then validate and inspect each. Build copies all catalog sources. The default preview loads the complete published room; preview/desk-lamp.html loads the metric lamp explicitly. The renderer currently shares geometry across copies of one asset. No daily scheduler is included in this repository.

## Rendering constraints
The active previews use SVG painter sorting. Intersecting geometry can show ordering artifacts; there is no shared WebGL depth buffer. The earlier WebGL renderer remains available for metric consumers. No transparent sorting, shadows, physics, GLB exporter or performance guarantees are included. Geometry buffers are cached; rendering is event-driven. Test representative low-end devices before choosing scene budgets. Do not use per-object camera scaling to make differently sized objects appear equal.

## Procedural SVG imports

`format: procedural-svg` version 2 preserves the published SVG functions while exposing **metre-based** dimensions, bounds, footprint and Y-up placement. The original native source remains Z-up/drawing-units in `sourceCoordinates`, with its original bounds and local support origin. Previous uncalibrated version 1 descriptors remain under each asset's versions/1.json for provenance and are not catalog placement entries.

Every imported asset references the same assets/lofi-night-room/calibration.json. The assumed study-desk worktop is 0.75 m above the finished floor. In the source the floor is z=5 and the desktop top z=33, so one source unit is 0.75/28 m. This shared uniform scale preserves every relative proportion. Right-handed axis conversion is [x,z,-y]. Source origins are subtracted before conversion; renderer/placement.js supplies the inverse and world-placement helpers. No viewport, thumbnail or camera term enters that conversion.

Dimensions and bounds are **estimated placement envelopes**, not measured manufacturer dimensions or exact mesh extents. The source grouping/framing envelopes are used as estimates. Mug steam and other visual effects are excluded from physical dimensions where identified. The drawer footprint includes the open extension. Record assumptions and improve the shared calibration or an asset's source envelope in a new version if better dimensions become available; do not rescale each prop to equal screen size.

Each entry has stable id/version/name, source (repository-relative JavaScript), entry (function name), calibrationFile and provenance source/license. Component entries name their library. The room has ordered sourceFiles and components. The raw framing size is preserved in sourceCoordinates.framingSize. Definitions load separately from preview/room.js, which owns the published UI lifecycle. The SVG itself is still a projected drawing, not a metric mesh export.

assets/lofi-night-room/assembly.json gives metre positions and unit scales for all 18 components, relative to the room's ground-centered origin. renderer/placement.js maps component source points to the same room world coordinates. This placement list is separate from the original lamp player's saved interactive scene format.

The study lamp uses `format: metric-svg`, version 2, and remains 0.24 × 0.48 × 0.26 m. Its geometry/material contract above is unchanged. Version 1 is immutable at versions/1.json; saved v1 arrangements are explicitly compatible and retain their version when re-saved.

## Kitchen batch discrete states (2026-10-23)

Metric parts may include `visibleWhen: {booleanStateKey: value}`. All listed conditions must match the instance state for the part to draw. This is discrete removal/refill, not an articulated joint: fixed joints, pivots and reference axes retain their existing meaning. Rest bounds include every authored part; active bounds are recomputed with `renderer/metric-state.js`. Removed pieces leave the scene. No decorative motions or material recolors count as new objects.

`supportSurfaces` lists usable local XZ polygons, local metre `height`, Y-up `normal`, and optional `availableWhen`. An empty array explicitly means no certified placement surface. The helper transforms available surface vertices and active geometry bounds into world coordinates. Supports are geometric placement hints, not load limits or collision physics.

`renderer/svg.js` accepts an asset or a Map of metric assets. A single camera and BSP polygon/edge painter order cover the entire mixed scene; near-plane clipping applies to faces and lines. BSP splits spanning faces to resolve occlusion rather than sorting whole triangles by average depth. This is still SVG, without WebGL, lighting or shadows. The ground grid is a background guide for above-ground objects. `camera.target`, distance, yaw and pitch only change the view. The kitchen inspection mode hides other instances for observation; whole-set mode restores them without changing placement or scale.

Open-ended cylinders/frusta may omit either cap independently. Baking funnel uses both cap flags for an unobstructed throat; the shell is a two-sided surface, with no wall thickness simulation.

## Utility v2 discrete operating model

Four utility assets retain immutable v1 sources and use v2 states. Fixed-pose toggle behavior remains supported. `dehumidify` and `empty-tank` actions use numeric humidity/water state and boolean wet/full indicators with an explicit positive-capacity `simulation` descriptor. A dehumidify action is one illustrative cycle, not elapsed real time or measured physical behavior. Emptying preserves humidity. A full tank or target humidity stops further cycles. `placementLockWhen` is an optional boolean condition honored by the metric preview's position/rotation controls (cart parking brake); it is not a physics collider. Additional actions are separate buttons. Old v1 utility placements are not silently migrated; unsupported versions fail explicitly.

## Opt-in horizontal support attachments (2026-11-09)

Scene instances may declare `attachment: {parentId, surfaceId, offset: [x,z], yaw}`. Offsets and yaw are in the parent's local metre/Y-up frame. Omit attachment for the existing independent-placement behavior. This extends optional scene metadata without changing asset or scene schemaVersion; older consumers that ignore it will not follow parents.

`renderer/attachments.js::resolveAttachments(instances, assets)` returns a resolved deep copy, following parent-first dependencies. Position is derived from the active named support height, parent world translation/yaw and local offset; child yaw inherits parent yaw plus its local yaw. The child bottom must be Y=0. Unit scales and yaw-only root rotations are required along the attachment chain. Convex horizontal support polygons are supported through conservative active-bounds corner containment. Exactly one surface with the selected ID must be active; state-conditioned surfaces may share an ID, e.g. the workstation top at .75 or 1.10 m. Resolve rejects invalid/missing/cyclic relations, unsupported transforms, unavailable/ambiguous surfaces and child overflow. It does not mutate the input on failure.

The scene loader validates and resolves saved relations. The shared metric preview resolves after actions or parent position/rotation edits, atomically reverting a rejected edit with a status message. Attached child transform fields are disabled; **Detach from support** preserves its current world pose. **Duplicate selected object** produces an independent detached copy, and duplicating a parent does not clone its children. Existing snapshots without attachments remain independent and retain their previous behavior. There is no click-to-bind editor; author relations in scene JSON. `saveScene` serializes current relations/transforms; direct code consumers must resolve after edits before rendering/saving.

Attachments are geometric layout relations, not load certification, physics, general moving-part parenting, automatic collision avoidance, sibling overlap detection, wall/ceiling attachment or continuous swept clearances. This cycle separately tests its sibling placements. A disappearing support rejects an action rather than silently dropping its contents. Imported procedural sources are not attachable; both child and parent require metric parts. Current operation metadata `motionRanges` documents endpoint values, axis, units and referenced pose part IDs; fixed-joint geometry still represents discrete poses, not interpolated joints.

## Wall and downward-soffit installation (2026-11-10)

An optional scene `mount: {parentId, surfaceId, anchorId, offset:[u,v]}` complements horizontal `attachment`; an instance must not specify both. Parent assets declare `installationSurfaces`, and fixtures declare `mountAnchors`. Each entry has stable `id`, `kind`, metre `position`, explicit `normal`, convex contact-envelope `polygon`, and optional boolean `availableWhen`. The `wall` kind maps `(u,v)` to parent `(X,Y)` at constant Z, with parent normal +Z and fixture anchor normal -Z. The `soffit` kind maps `(u,v)` to `(X,Z)` at constant Y, with parent normal -Y and fixture anchor normal +Y. Region coordinates are offsets from the surface/anchor position. These are installation contact envelopes, not necessarily full silhouette or continuous load-bearing patches; e.g. a pendant canopy contacts the beam, while its shade overhangs.

`resolveAttachments` resolves either relation in one parent-first graph, including supported children of mounted fixtures. Unit scale and yaw-only root rotations still apply. Mounted fixture yaw inherits the parent's yaw; no extra local mount rotation is supported. The fixture anchor aligns exactly to the selected surface point. Its contact envelope must fit the parent region, normals must oppose, and active geometry must not cross behind a wall plane or above a soffit. All checks happen on a copy; cycles, mutually specified bindings, unavailable/ambiguous anchors/surfaces, wrong kinds/normals, unsupported transforms and overflow reject atomically. Schema validation checks finite coordinates, convex nonzero-area polygons, unique IDs and canonical normals. Geometric mounting-region validity on the host geometry is additionally checked in batch tests/review.

Scene load/save preserves `mount`, and the shared preview applies the same atomic action/edit semantics as horizontal attachments. Bound fields are disabled, **Detach from parent** preserves world pose, and duplication creates one detached independent copy without cloning its descendants. Source coordinates remain bottom/contact-centered with scale one: a fixture's source is not pre-raised to installation height. For retracting blinds, this origin refers to the lowered rest pose; raised active bounds can start above local Y=0. Stored bounds/footprints still cover all authored endpoints.

This establishes vertical face and downward horizontal installation only. It is not an arbitrary plane/hinge solver, structural/loading certification, electrical circuit, automatic wall join, roof generator, mount-authoring UI or swept collision system. Conservative anchor envelopes may bridge separated real mounting plates. Sibling/room collision is not automatically prevented and must be reviewed in the assembly. The current study includes an intentional bounded overlap at its rear/side wall junction; other inter-asset endpoint intersections are rejected by its tests. Older scenes and source versions remain unchanged.
