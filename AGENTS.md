# Contributor instructions
Read docs/asset-spec.md before creating an asset. Keep asset sources separate from renderer and preview UI. Every placeable asset, including newly produced daily props, uses 1 unit = 1 metre, Y-up, XZ ground, contact-center origin and default scale [1,1,1]. The catalog supports metric-svg and procedural-svg. Imported SVG assets preserve original source coordinates separately and require a documented physical calibration plus axis transform; viewport or thumbnail fitting is never a physical calibration. Record estimated dimensions and their reference honestly. Preserve immutable source versions when geometry or semantics change. Do not commit credentials, private conversations, generated dist files, or dependencies. Run npm run validate, npm test and npm run build before a commit. For visual changes inspect desktop and narrow-screen Chromium previews, switching, rotation, zoom and duplicate state independence where supported. Never claim checks that were not run. Do not force push or deploy without explicit authorization.

## Production scope and selection

Read docs/production-policy.md and docs/catalog-balance.md before planning a cycle, then refresh the complete catalog inventory and recent batch distribution against current sources. The collection covers everyday home, office and commercial interiors: props, furniture, fixtures, equipment and machines. Check space, actual physical size, function, existing previews and semantic duplicates before choosing a theme. Separate complete rooms, imported compound/component groups and independent objects; keep multi-purpose tags and do not double-count reused parts or scenes.

Prioritize missing interior roles and mixed-size furnished scenes. Do not default to ten small tools, generate easy filler to reach a count, or impose permanent quotas. Reuse existing props alongside needed medium/large furniture and equipment. For complex work prefer fewer verified deliverables and honest partial-completion reporting. A removable crank/cover/handle is not proof of meaningful machine operation; define and verify the intended ordinary function or label the depiction static. Preserve all existing asset, placement, support, part-axis/state, occlusion, independent-instance save/restore, thumbnail and visual-validation contracts. Update the cumulative inventory, gap review and next priorities with each production cycle.
