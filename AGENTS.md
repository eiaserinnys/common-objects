# Contributor instructions
Read docs/asset-spec.md before creating an asset. One unit is one metre; never normalize asset geometry to a camera or thumbnail. Use Y-up, XZ ground, contact-center origin and default scale [1,1,1]. Record estimated dimensions honestly. Keep source JSON separate from renderer and preview UI. Preserve immutable asset versions when geometry or semantics change. Do not commit credentials, private conversations, generated dist files, or dependencies. Each asset requires stable part IDs, bounds, clearance footprint, state defaults and provenance. Run npm run validate, npm test and npm run build before a commit. For visual changes inspect desktop and narrow-screen Chromium previews, switching, rotation, zoom and duplicate state independence. Never claim checks that were not run. Do not force push or deploy without explicit authorization.
